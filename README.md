## 2. 영상 생성 기본 규칙

1. **해상도:** `720p` (최고 화질).
2. **길이:** 사용자가 따로 말하지 않으면 **15초**.
3. **시작 이미지:** 사용자가 첨부한 이미지를 **첫 프레임**으로 사용.
4. **소리:** 기본은 **배경음악 없음, 대사 없음**. 사용자가 특정 소리를 원할 때만 넣기.
5. **프롬프트 공개:** 영상을 보여줄 때마다 사용한 **영어 프롬프트**와 **한글 번역**을 함께 보여주기. 한글은 읽기 쉽게 줄바꿈하기.
6. **오디오 검사 (필수):**
   1. 생성 후 음량 측정:
      ```bash
      ffmpeg -i in.mp4 -af volumedetect -vn -f null -
      ```
   2. 거의 무음(예: `max_volume: -44 dB` 수준)이면 **실패**예요 → 다시 생성하거나 볼륨을 키우기.
   3. **3초 구간별**로도 음량을 확인하기. 생성기가 약 10초 이후 소리를 페이드아웃하는 경향이 있어요.
      ```bash
      for s in 0 3 6 9 12; do echo "== ${s}s"; ffmpeg -ss $s -t 3 -i in.mp4 -af volumedetect -vn -f null - 2>&1 | grep -E "mean_volume|max_volume"; done
      ```
   4. 사용자가 **음악이 끝까지 이어지길** 원하면: 앞부분 오디오 구간을 잘라(`atrim`) 뒤에 `acrossfade`로 이어 붙여 연장하고, 볼륨을 맞추기.
7. **피드백 반복:** 사용자는 피드백을 주며 다듬는 걸 좋아해요. 예: 카메라 구도(미디엄 클로즈업, 미디엄 롱샷), 더 활발하고 사실적인 몸짓 등. 요청을 정확히 반영해서 다시 생성하기.

### 4-2. 비밀번호 잠금

- 페이지를 열면 비밀번호를 물어봐요. **사용자가 비밀번호를 알고 있어요.** (이 문서에는 적지 않아요.)
- `index.html` 안에 **솔트를 붙인 SHA-256 해시**로 저장되어 있어요. "이 기기에서 기억하기"는 `localStorage`를 사용해요.
- **비밀번호 바꾸는 법:**
  1. 새 비밀번호의 해시 계산:
     ```bash
     printf '%s' 'vg-salt-kmuse:새비밀번호' | sha256sum
     ```
  2. `index.html`의 잠금 스크립트에 있는 `H` 값을 새 해시로 교체 → 커밋 → 푸시.
- 참고: 이건 **가벼운 잠금**일 뿐 진짜 보안은 아니에요. 시트와 Drive는 어차피 링크로 공개되어 있어요. 페이지에는 `noindex`가 설정되어 있어요.

### 4-3. 자동 갱신 원리

1. 페이지는 열 때마다 시트를 **실시간(gviz JSON)** 으로 읽고, 이후 **60초마다** 다시 읽어요.
   → 시트에 새 행을 추가하면 **약 1분 안에** 갤러리에 나타나요 (처음에는 Drive 플레이어로 재생).
2. Google Drive는 다른 사이트에서의 직접 영상 재생을 막아요(403). 그래서 영상은 저장소에 **직접 호스팅**해요:
   - 파일: `videos/<driveVideoId>.mp4` (`+faststart`로 리먹스)
   - 목록: `videos/index.json`
3. 워크플로 `.github/workflows/sync-videos.yml`이 **15분마다** (그리고 수동 `workflow_dispatch`로도) 실행돼요:
   1. 시트의 `I`열(영상ID)을 읽고
   2. 새 영상을 Drive에서 다운로드: `https://drive.usercontent.google.com/download?id=<id>&export=download`
   3. 리먹스한 뒤 `github-actions[bot]`으로 커밋
   4. Pages가 약 1분 뒤 재빌드
   - 스크립트: `scripts/sync-videos.sh`
4. ✅ **결론: 시트에 행만 추가하면 다른 작업은 필요 없어요.** 약 15분 안에 갤러리가 스스로 갱신되고 기본(네이티브) 플레이어로 전환돼요.

### 4-4. 기능

- 카드마다 기본 플레이어 컨트롤, **한 번에 하나의 영상만 재생**
- **'크게 ⛶'** 전체 화면 뷰어: `←`/`→` 이전/다음, `F` 전체화면, `P` 프롬프트 패널 토글, `Esc` 닫기
- 접을 수 있는 EN/KO 프롬프트 + 복사 버튼
- 검색, 새로고침, 시트 열기 링크
- 32인치 4K 모니터에 맞춘 전체 폭 레이아웃

### 4-5. 한도와 주의사항

- GitHub Pages 사이트 용량은 약 **1GB** → 영상당 4–10MB 기준 대략 **100–150개**.
  - 가득 차면: 페이지용 사본을 압축하거나 오래된 것을 삭제 (원본은 Drive에 그대로 남아요).
- 저장소에 **60일간 활동이 없으면** GitHub가 예약 워크플로를 일시 중지할 수 있어요 → 저장소의 **Actions** 탭에서 다시 활성화하기.

### 4-6. 되돌리기 (롤백)

- git 히스토리(**Commits**)로 관리돼요. 봇에게 "○○ 커밋으로 되돌려줘"라고 요청하면 돼요.

### 4-7. 페이지를 수정하려면 (봇용)

봇에게 GitHub 접근 권한이 필요해요. 박스에서:

1. 로그인 (디바이스 코드 방식):
   ```bash
   gh auth login -h github.com -p https -w
   ```
   - 표시된 코드를 사용자가 `https://github.com/login/device` 에 입력해요.
2. git 연동:
   ```bash
   gh auth setup-git
   ```
3. 클론 → 수정 → 푸시:
   ```bash
   git clone https://github.com/kmuse996-bot/video-gallery.git
   cd video-gallery
   git pull --rebase
   # index.html 수정
   git add -A && git commit -m "변경 내용" && git push
   ```

## 5. 문제 해결 FAQ

| 증상 | 해결 방법 |
|---|---|
| Drive에서 영상이 재생되지 않아요 | `.mov`로 리먹스해서 다시 업로드하기 (3-a 명령어). |
| 시트에 시작 이미지가 안 보여요 | 파일이 **링크로 공유**되어 있는지 확인하고, `https://lh3.googleusercontent.com/d/<id>` 형식 URL을 쓰기. |
| 시트에 `#REF!`가 떠요 | `I2:K`에 뭔가 입력된 거예요 → 그 셀들을 **지우기**. |
| 갤러리에 예전 내용이 보여요 | 강력 새로고침: `Ctrl+Shift+R`. |
| 새 영상이 아직 Drive 플레이어로 재생돼요 | 15분 동기화를 기다리거나, 저장소 **Actions** 탭에서 `sync-videos` 워크플로를 수동 실행(`Run workflow`). |
| GitHub 가입 시 "access temporarily restricted" | 네트워크/IP 차단이에요. 나중에 다시 시도하거나 모바일 데이터로 시도. |
| 예약 워크플로가 안 돌아요 | 60일 비활동으로 중지됐을 수 있어요 → Actions 탭에서 다시 활성화. |
